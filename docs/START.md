# Подготовка и первый запуск

[К началу курса](../README.md)

Нужны браузер, GitHub-аккаунт, подготовленный Docker с Linux-контейнерами и Compose. Редактировать файлы можно в установленном редакторе. Git удобен, но если его нет, используйте браузерный маршрут из [правил сдачи](SUBMISSION.md). Отдельный Python на ПК для студенческих работ не требуется.

## 1. Получите свою копию

Создайте Fork репозитория курса в свой аккаунт. Затем скачайте **свою копию** через Code → Download ZIP, распакуйте её, например в `Documents/DevOps-course`. Не работайте внутри ZIP. Если Git установлен, вместо ZIP используйте клонирование своей копии.

Откройте PowerShell/терминал в папке, где находятся `README.md` и `compose.yaml`.

```text
docker version
docker compose version
docker info --format '{{.OSType}}'
```

Ожидаются Client и Server, версия Compose и `linux`. Если Server недоступен, не меняйте настройки системы — сообщите преподавателю. Все дальнейшие команды Docker одинаковы в PowerShell и обычном Linux-терминале.

## 2. Запустите подготовленный стенд

Преподаватель заранее собирает образ `devops-course:base` и образ диагностических инструментов. Проверка:

```text
docker image inspect devops-course:base
docker image inspect devops-course-tools:base
docker compose config
docker compose up -d
docker compose ps
```

Если образ не найден, нужна [подготовка преподавателем](../teacher/PREFLIGHT.md), а не случайный образ из интернета. Через несколько секунд `api` и `web` должны быть `healthy`.

Откройте [http://localhost:8080](http://localhost:8080), отправьте одну заявку и проверьте её номер в списке. Не вводите реальные персональные данные: приложение использует только учебные виды неисправностей.

## 3. Что где работает

```text
Ваш браузер → localhost:8080 → web:8000 → api:8000 → том requests
```

`localhost` в браузере — ваш компьютер. `api` внутри сети Compose — имя контейнерного сервиса. Данные заявок находятся в Docker-томе, а не в Git-репозитории. Поэтому для сдачи нужны конфигурации и подтверждения, а не файл базы.

## 4. В конце занятия

```text
docker compose stop
```

Это сохраняет контейнеры и тома. Для продолжения: `docker compose up -d`. Для остановки всех включённых учебных профилей: `docker compose --profile "*" stop`.

Не используйте `docker system prune`, удаление всех контейнеров или `down -v`: можно потерять данные и чужую работу. На одном ПК работайте с одной согласованной папкой проекта. Параллельные копии требуют разных портов и имён проектов — это настраивает преподаватель.

## 5. Что приложить к сдаче

Для каждой работы создайте `evidence/ID.md` по [шаблону](../templates/report.md): команды, важный результат, ваш вывод, ответ на вопрос. Короткий содержательный отчёт лучше полного журнала терминала.
