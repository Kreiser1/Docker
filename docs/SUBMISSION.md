# Сдача работ через GitHub

[К началу курса](../README.md)

## Один студент — одна копия на курс

Нажмите Fork в репозитории курса и создайте свою копию. Имя может остаться `DevOps-course`. Сообщите преподавателю GitHub-login и группу. ФИО и баллы в публичные файлы не добавляйте; используйте выданный код студента.

**Pull request направляйте в `main` своей копии**, не в репозиторий преподавателя. Это личная сдача, а не изменение общего курса. Преподавателю нужен доступ к содержимому и ссылке; для приватной копии добавьте его как участника.

## Маршрут с установленным Git

Вместо адреса в примере подставьте URL своей копии из Code → HTTPS. Git не устанавливаем самостоятельно.

```text
git clone https://github.com/YOUR-LOGIN/DevOps-course.git
cd DevOps-course
git switch -c kt1
```

Выполните работы. Добавьте только относящиеся к ним файлы; пример для первой КТ:

```text
git add evidence
git diff --cached
git commit -m "KT1: diagnosis and evidence"
git push -u origin kt1
git rev-parse HEAD
```

На GitHub откройте Pull requests → New pull request. Укажите **base repository: ваша копия**, **base: main**, **compare: kt1**. Вставьте полученный SHA в описание PR. Для следующих КТ используйте `kt2`, `kt3`, `kt4` от обновлённого `main`.

## Маршрут без Git на компьютере

1. В своей копии на GitHub создайте ветку `kt1` через переключатель веток.
2. Локально работайте в распакованной папке и проверяйте изменения Docker-командами.
3. В браузере выберите свою ветку. Через Add file → Upload files загрузите изменённые файлы с сохранением структуры; через Add file → Create new file можно задать путь `evidence/K1-01.md`.
4. Нажмите Commit changes, затем откройте PR из `kt1` в `main` своей копии.
5. На вкладке Commits скопируйте SHA последнего коммита в описание PR. Проверьте Files changed: файлы должны лежать по правильным путям.

Для workflow файл должен находиться именно в `.github/workflows/student-ci.yml`; его удобно создать в браузерном редакторе, вставив текст локального файла. Не переносите `.env`, базы, архивы образов и кэш.

## Что писать в PR

Заполните автоматически появившийся [шаблон](../.github/pull_request_template.md): группа/код, ID работ, SHA, ссылки на отчёты, инструкция проверки, Actions для КТ 3, известные проблемы. Не переписывайте SHA в самом коммитируемом отчёте после каждого коммита — у такого изменения опять будет новый SHA.

Отправьте ссылку преподавателю через используемый группой учебный канал или покажите на занятии. PR сам по себе не гарантирует, что преподаватель узнал о сдаче. Канал и сроки объявляются для каждой группы отдельно.

## Проверка и доработка

- До проверки не сливайте PR. Замечание преподавателя содержит невыполненный критерий.
- Исправляйте в той же ветке, обновляйте подтверждения и SHA в описании PR, сообщайте о готовности повторной проверки.
- После приёмки слейте PR в свой `main`. В Git: `git switch main`, затем `git pull`. В браузерном маршруте скачайте обновлённую копию либо продолжайте в той же локальной папке, сверив её с принятыми изменениями.
- Если следующая КТ начинается раньше проверки предыдущей, начните её от текущей рабочей ветки и укажите зависимость в новом PR; преподаватель оценивает только перечисленные ID, без повторного начисления.
- Зелёный Actions и merge подтверждают технические действия, но баллы выставляет преподаватель по рубрике.

GitHub поддерживает обсуждение и проверку изменений в PR: [официальная инструкция](https://docs.github.com/en/pull-requests/how-tos/review-pull-requests).
