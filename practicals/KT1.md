# КТ 1. Практические работы — 15 баллов

[Теория](../theory/KT1.md) · [Правила сдачи](../docs/SUBMISSION.md) · [Курс](../README.md)

Все команды выполняйте из корня своей копии, если явно не указано «внутри контейнера». Для КТ 2–4 нужны результаты предыдущих этапов. Рабочую копию Compose переключаем явно через `-f`; это тот же проект и те же тома, не два параллельных стенда.

## K1-01. Путь изменения — 3 баллов

**Задача.** Нарисуйте путь изменения формы заявки от идеи до пользователя. Назовите действия разработчика, тестировщика и эксплуатации. Найдите одно место, где ошибка может остаться незамеченной. Предложите проверку.

**Сдать:** файлы изменений, `evidence/K1-01.md` с командами, наблюдениями и выводом; для CI — ссылки на прогоны, для панели — JSON. Если работа устная/схематическая, достаточно схемы и ответа в отчёте.

**Критерии:** Схема пути — 1; роли и ответственность — 1; риск и проверка — 1.

**Проверка понимания:** Почему готовый код ещё не означает работающий сервис?

## K1-02. Linux и диагностика — 5 баллов

**Задача.** Запустите стенд по docs/START.md. Выполните docker compose run --rm tools sh. Внутри выполните pwd, ls, ps -ef, ss -lnt и curl -i http://127.0.0.1:8000/health. Найдите процесс python app.py и порт 8000. Выйдите через exit. Прочитайте docker compose logs --tail=20 api.

**Сдать:** файлы изменений, `evidence/K1-02.md` с командами, наблюдениями и выводом; для CI — ссылки на прогоны, для панели — JSON. Если работа устная/схематическая, достаточно схемы и ответа в отчёте.

**Критерии:** Процесс найден и объяснён — 1; порт найден — 1; HTTP-ответ прочитан — 1; значимая строка лога объяснена — 1; связь процесса, порта и ответа — 1.

**Проверка понимания:** Почему tools видит процессы api, а не все процессы компьютера?

## K1-03. Простой отказ — 5 баллов

**Задача.** Откройте localhost:8080 и создайте заявку. Выполните docker compose stop api. Обновите страницу и список. Сравните localhost:8080/health и localhost:8080/api/requests. Прочитайте docker compose ps -a и docker compose logs --tail=20 web. Сформулируйте причину. Восстановите docker compose start api и создайте новую заявку.

**Сдать:** файлы изменений, `evidence/K1-03.md` с командами, наблюдениями и выводом; для CI — ссылки на прогоны, для панели — JSON. Если работа устная/схематическая, достаточно схемы и ответа в отчёте.

**Критерии:** Симптом до/после — 1; гипотеза — 1; лог и статус подтверждают её — 1; восстановление — 1; новая заявка подтверждена — 1.

**Проверка понимания:** Почему health у web остался успешным?

## K1-04. Первая GitHub-сдача — 2 баллов

**Задача.** По docs/SUBMISSION.md создайте свою копию, ветку kt1 и PR в main своей копии. Добавьте отчёты предыдущих работ. В описании укажите группу, код, ID и SHA. Покажите преподавателю, какие файлы изменились.

**Сдать:** файлы изменений, `evidence/K1-04.md` с командами, наблюдениями и выводом; для CI — ссылки на прогоны, для панели — JSON. Если работа устная/схематическая, достаточно схемы и ответа в отчёте.

**Критерии:** Доступный PR с файлами и SHA — 1; объяснение собственного изменения — 1.

**Проверка понимания:** Чем ссылка на PR полезнее ссылки только на главную страницу репозитория?

После выполнения проверьте файлы в PR и передайте ссылку преподавателю. При ошибке приложите фактический вывод, а не предполагаемый успешный результат.
