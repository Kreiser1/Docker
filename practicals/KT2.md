# КТ 2. Практические работы — 25 баллов

[Теория](../theory/KT2.md) · [Правила сдачи](../docs/SUBMISSION.md) · [Курс](../README.md)

Все команды выполняйте из корня своей копии, если явно не указано «внутри контейнера». Для КТ 2–4 нужны результаты предыдущих этапов. Рабочую копию Compose переключаем явно через `-f`; это тот же проект и те же тома, не два параллельных стенда.

## K2-01. Образ и контейнер — 4 баллов

**Задача.** На работающем стенде выполните docker image inspect devops-course:base и docker compose ps. Найдите образ и два его экземпляра. Остановите только web командой docker compose stop web, проверьте отсутствие страницы, затем docker compose start web и повторите заявку.

**Сдать:** файлы изменений, `evidence/K2-01.md` с командами, наблюдениями и выводом; для CI — ссылки на прогоны, для панели — JSON. Если работа устная/схематическая, достаточно схемы и ответа в отчёте.

**Критерии:** Свойства образа — 1; два контейнера и их роли — 1; остановка/запуск — 1; подтверждение заявки и объяснение — 1.

**Проверка понимания:** Удаляется ли образ при остановке web?

## K2-02. Свой Dockerfile — 7 баллов

**Задача.** По templates/Dockerfile.example создайте lab/Dockerfile. Используйте bootstrap как объяснённый образец. Добавьте LABEL course.student с вашим кодом. Соберите: docker build -f lab/Dockerfile -t devops-student:v1 lab. Запустите docker run --rm -d --name student-web -p 127.0.0.1:8081:8000 -e ROLE=web devops-student:v1. Проверьте localhost:8081/health. Здесь нет API: приём заявок проверяется в следующей работе. Посмотрите docker logs student-web и остановите docker stop student-web.

**Сдать:** файлы изменений, `evidence/K2-02.md` с командами, наблюдениями и выводом; для CI — ссылки на прогоны, для панели — JSON. Если работа устная/схематическая, достаточно схемы и ответа в отчёте.

**Критерии:** Dockerfile: корректные COPY/CMD — 1, USER и права /data — 1; сборка — 1, свой LABEL в image inspect — 1; запуск — 1, health — 1; объяснение инструкции — 1.

**Проверка понимания:** Почему EXPOSE не заменяет -p?

## K2-03. Compose и сохранность данных — 7 баллов

**Задача.** Скопируйте compose.yaml в compose.student.yaml. В api и web замените image на devops-student:v1. Остальные сервисы пока не меняйте. Остановите основной стенд: docker compose stop. Далее используйте только docker compose -f compose.student.yaml. Проверьте config, выполните up -d и создайте заявку. Зафиксируйте её номер. Выполните up -d --no-deps --force-recreate api. После готовности проверьте старую и создайте новую заявку.

**Сдать:** файлы изменений, `evidence/K2-03.md` с командами, наблюдениями и выводом; для CI — ссылки на прогоны, для панели — JSON. Если работа устная/схематическая, достаточно схемы и ответа в отчёте.

**Критерии:** Два сервиса на своём образе — 1; API_URL и внутренняя сеть объяснены — 1; порты — 1; том — 1; новая заявка — 1; старая сохранилась после пересоздания — 1; инструкция запуска — 1.

**Проверка понимания:** Почему нельзя хранить базу только в изменяемом слое контейнера?

## K2-04. Registry — 4 баллов

**Задача.** Запустите docker compose --profile registry up -d registry. Выполните docker tag devops-student:v1 localhost:5000/workshop:v1, docker push localhost:5000/workshop:v1, docker pull localhost:5000/workshop:v1. Сохраните digest из вывода push/pull. Проверьте docker image inspect localhost:5000/workshop:v1. Локальный registry не требует аккаунта. При сетевой ошибке покажите её преподавателю; защиту системы не отключайте.

**Сдать:** файлы изменений, `evidence/K2-04.md` с командами, наблюдениями и выводом; для CI — ссылки на прогоны, для панели — JSON. Если работа устная/схематическая, достаточно схемы и ответа в отчёте.

**Критерии:** Тег с адресом registry — 1; push — 1; pull — 1; digest и объяснение tag/digest — 1.

**Проверка понимания:** Почему push не запускает сервис?

## K2-05. Ошибка конфигурации — 3 баллов

**Задача.** В compose.student.yaml временно замените API_URL у web на http://api:9999. Выполните docker compose -f compose.student.yaml up -d web. Проверьте список заявок и лог web. Объясните ошибку, восстановите 8000, повторите up -d web и пользовательский сценарий.

**Сдать:** файлы изменений, `evidence/K2-05.md` с командами, наблюдениями и выводом; для CI — ссылки на прогоны, для панели — JSON. Если работа устная/схематическая, достаточно схемы и ответа в отчёте.

**Критерии:** Воспроизведённый симптом — 1; связь ошибки с портом — 1; исправление и успешная заявка — 1.

**Проверка понимания:** Какой порт нужен между контейнерами: 8080 или 8000?

После выполнения проверьте файлы в PR и передайте ссылку преподавателю. При ошибке приложите фактический вывод, а не предполагаемый успешный результат.
