## K4-01. Логи и доступность — 6 баллов

**Задача.** Верните исправный compose.student.yaml. Запустите docker compose -f compose.student.yaml up -d. Создайте заявку. Сопоставьте время браузерного действия с docker compose -f compose.student.yaml logs --tail=30 api и web. Откройте /health и /api/requests через порт 8080, сравните назначение проверок.

**Сдать:** файлы изменений, `evidence/K4-01.md` с командами, наблюдениями и выводом; для CI — ссылки на прогоны, для панели — JSON. Если работа устная/схематическая, достаточно схемы и ответа в отчёте.

**Критерии:** Успешный сценарий — 1; лог web — 1; лог api — 1; связь времени/действия — 1; проверка health — 1; различие уровней готовности — 1.

**Проверка понимания:** Какая проверка заметит отказ зависимости?

## K4-02. Prometheus и Grafana — 8 баллов

**Задача.** Выполните docker compose -f compose.student.yaml --profile monitoring up -d. Откройте localhost:9090/targets: обе цели должны быть UP. Выполните up{job="workshop"}. В Grafana localhost:3000 создайте dashboard и панель с источником Workshop Prometheus. Используйте запрос devops_http_requests_total{role="web",status="200"}, затем rate(devops_http_requests_total{role="web",status="200"}[1m]). Несколько раз обновите список заявок, подождите 30–60 секунд. Добавьте название и единицу requests/sec для rate. Экспортируйте JSON в evidence/K4-02-dashboard.json.

**Сдать:** файлы изменений, `evidence/K4-02.md` с командами, наблюдениями и выводом; для CI — ссылки на прогоны, для панели — JSON. Если работа устная/схематическая, достаточно схемы и ответа в отчёте.

**Критерии:** Обе цели UP — 1; up объяснён — 1; счётчик прочитан — 1; rate объяснён — 1; панель — 1; название/единица — 1; изменение после нагрузки — 1; JSON и вывод — 1.

**Проверка понимания:** Почему счётчик может сброситься, хотя заявки сохранены?

## K4-03. Ansible и повторный запуск — 8 баллов

**Задача.** Выполните docker compose run --rm ansible demo.yml дважды: второй запуск должен показать changed=0. По ansible/banner.yml.example создайте ansible/banner.yml. Добавьте workshop_message с кодом студента, затем задачу copy для /data/banner.txt, content из этой переменной, mode 0644, owner/group 10001. Выполните docker compose run --rm ansible banner.yml дважды. Проверьте localhost:8080/api/banner. Измените сообщение и повторите применение; новый текст должен появиться в API.

## K4-04. Учебный инцидент — 8 баллов

**Задача.** Зафиксируйте одну старую заявку. При работающем мониторинге выполните docker compose -f compose.student.yaml stop api. Попробуйте получить список. Через 10–15 секунд сохраните up для api, счётчик web status=503 и строку upstream_unavailable. Выполните docker compose -f compose.student.yaml start api. Дождитесь UP, проверьте старую и создайте новую заявку. Запишите короткую хронологию симптом → причина → действие → проверка.

**Сдать:** файлы изменений, `evidence/K4-04.md` с командами, наблюдениями и выводом; для CI — ссылки на прогоны, для панели — JSON. Если работа устная/схематическая, достаточно схемы и ответа в отчёте.

**Критерии:** Исходное состояние — 1; сбой — 1; up — 1; HTTP 503 и лог — 1; причина — 1; восстановление — 1; старые данные и новая заявка — 1; хронология — 1.

**Проверка понимания:** Это rollback версии или восстановление процесса?
