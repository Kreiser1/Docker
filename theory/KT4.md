# КТ 4. Мониторинг, IaC и итог — необходимый минимум

[Работы КТ 4](../practicals/KT4.md) · [Курс](../README.md)

## 1. Работает ли сервис для пользователя

У сервиса есть несколько уровней состояния: процесс запущен, порт отвечает, зависимость доступна, пользовательская операция выполнена. Наша `/health` проверяет первый уровень; создание заявки проверяет всю цепочку. Не называйте процесс healthy доказательством того, что заявки принимаются.

**Лог** описывает событие: когда произошла ошибка, в каком компоненте, какой запрос затронут. **Метрика** — числовое измерение во времени: число запросов, частота ошибок, длительность. Метрика помогает заметить проблему; лог помогает разобраться в конкретном событии.

## 2. Prometheus и Grafana

Приложение отдаёт `/metrics` в текстовом формате. Prometheus периодически читает этот endpoint — выполняет scrape — и сохраняет временные ряды. Grafana запрашивает ряды у Prometheus и рисует панели. Grafana сама не превращает логи в метрики.

В подготовленном стенде Prometheus обращается к `api:8000` и `web:8000` каждые 5 секунд. Сам Prometheus доступен в браузере на 9090, Grafana — на 3000. Внутри Grafana адрес источника — `http://prometheus:9090`, а не localhost вашего компьютера.

Полезные запросы:

```promql
up{job="workshop"}
devops_http_requests_total{role="web",status="503"}
rate(devops_http_requests_total{role="web",status="503"}[1m])
```

`up` создаёт Prometheus: 1 означает успешный scrape, 0 — неуспешный. Это не гарантия успешной заявки. `devops_http_requests_total` — счётчик HTTP-ответов нашего приложения по роли и статусу, без health/metrics-запросов. `rate` оценивает скорость роста счётчика; для неё нужно несколько точек за интервал.

После перезапуска процесса собственный счётчик начинается заново. Prometheus учитывает сбросы при rate. Нельзя интерпретировать это как отрицательное число заявок или потерю базы. Данные заявок и метрики — разные данные.

## 3. Минимальная полезная панель

Название должно объяснять смысл («Ошибки web: HTTP 503 в секунду»), запрос — выбирать нужный ряд, единица — соответствовать значению. Покажите здоровый период и момент сбоя. Скриншот без запроса и объяснения не показывает, понимаете ли вы метрику. Экспорт JSON позволяет повторить вашу панель.

## 4. Infrastructure as Code и Ansible

IaC — описание желаемого состояния инфраструктуры в файлах с историей изменений. Вместо инструкции «на каждой машине вручную создай файл» можно хранить правило «файл должен иметь это содержимое и права».

Ansible использует inventory (цели выполнения), playbook (сценарий), tasks (задачи) и modules (действия). В учебном стенде цель — localhost **внутри контейнера Ansible**, имеющего доступ только к учебному тому. SSH и установка Ansible на Windows не нужны. Это демонстрирует управление состоянием, но не заменяет практику с удалённым сервером.

Модуль `ansible.builtin.copy` сравнивает требуемое содержимое файла с текущим. Первый запуск может показать `changed=1`, повтор без изменений — `changed=0`. Это **идемпотентность**: повторное применение уже достигнутого состояния не меняет его снова.

Образец [demo.yml](../ansible/demo.yml) создаёт `/data/demo.txt`. В своей работе создайте `/data/banner.txt` с текстом из переменной. API читает этот файл при обращении к `/api/banner`, поэтому результат виден без пересборки приложения.

YAML — данные со значимыми отступами. `vars` хранит переменные; выражение `{{ workshop_message }}` подставляет значение. Права `0644` означают, что владелец может писать, остальные читать. В этом стенде UID/GID 10001 соответствует процессу приложения. Преподаватель заранее готовит контейнер и том; менять права Windows не нужно.

## 5. Инцидент и восстановление

Запишите время и симптом, сохраните метрику и лог, сформулируйте причину, выполните минимальное исправление, повторите пользовательский сценарий. В этой КТ управляемый инцидент — остановка API. Страница web остаётся доступной, но заявки не проходят; после запуска API нужно проверить новую заявку и сохранность старых.

Восстановление остановленного процесса — не то же самое, что rollback версии. Rollback возвращает предыдущий работавший образ/конфигурацию. На защите нужно объяснить, какой из вариантов использован и почему.
